Why ZeroVault

Credential vaults are honeypots. So we removed the vault.

Conventional AI gateways centralize every provider key in their own database and mint “virtual keys” on top — more secrets, bigger blast radius. ZeroVault inverts the model.

Devices carry certificates

Every agent authenticates with an mTLS client certificate signed by your private CA. No valid certificate — the TLS handshake fails before a byte of HTTP is spoken.

Keys pass through, in memory

Provider API keys live in the device's secure store and travel inside each request. The gateway forwards them verbatim and never logs headers, bodies, or query strings.

A lost phone is one revocation

Revoke one certificate (CRL) or drop one CN from the allowlist. Everyone else keeps working. Rate limits and body caps contain a stolen cert until you do.

Provider coverage

21 providers. One certificate. One URL.

Routing is by path prefix — /openai/v1/chat/completions reaches api.openai.com untouched. Every route was verified against the provider's live API documentation; deprecated APIs (Google PaLM, 01.AI) are excluded by design. Operators add custom routes with one EXTRA_UPSTREAMS entry.

Quickstart

Live in an afternoon

Three interchangeable gateway implementations — Node.js (zero dependencies), Go (single static binary), Python (FastAPI) — behave identically. Pick one; hardened installers and per-runtime runbooks ship in the repo.

1

Generate identities

# on your offline CA machine
./generate-certs.sh init proxy.example.com
./generate-certs.sh client phone-001
# → client-phone-001.p12 for the device
2

Start the gateway

# docker…
docker compose --profile go up -d
# …or from scratch on a VPS
sudo deploy/install/install-go.sh
3

Point your agent

// official SDKs: one URL change
new Anthropic({
  baseURL: "https://proxy:8443/anthropic",
  httpAgent: client.httpsAgent,
})
Developer SDK

Four SDKs, one contract

JavaScript/TypeScript, Python, Kotlin/Android, Swift/iOS — each wires up the device certificate, pins your CA, applies the right auth header per provider (x-api-key, x-goog-api-key, Bearer), streams SSE, and throws typed errors. None of them ever stores a key: pass keys per request or supply a keyProvider callback backed by Keychain / Keystore. Full guide: docs/SDK.md.

// zerovaultproxy (npm) — Node 18+, zero dependencies
const { ZeroVaultProxyClient } = require('zerovaultproxy');

const client = new ZeroVaultProxyClient({
  proxyUrl: 'https://proxy.example.com:8443',
  cert: fs.readFileSync('device.crt'), key: fs.readFileSync('device.key'),
  ca: fs.readFileSync('ca.crt'),                    // pinned
  keyProvider: (p) => secrets.get(p),               // keys stay in your store
});

const res = await client.request('anthropic', '/v1/messages', {
  headers: { 'anthropic-version': '2023-06-01' },
  json: { model: 'claude-sonnet-4-5', max_tokens: 200,
          messages: [{ role: 'user', content: 'hello' }] },
});

// SSE streaming
for await (const ev of client.stream('openai', '/v1/chat/completions',
    { json: { model: 'gpt-4o-mini', stream: true, messages } })) {
  render(ev.data);
}

Security

Audited line by line

The full audit — threat model, 11 findings with fixes, residual risks, operator checklist — ships as SECURITY.md in the repo. Highlights:

0
credentials at rest on the gateway
11
audit findings fixed & re-tested
365
day device-cert auto-expiry

Forward secrecy, always

TLS 1.3 by default; the optional 1.2 fallback allows ECDHE+AEAD suites only. Recorded traffic can never be decrypted later, even if the server key leaks.

Contained blast radius

Per-device token-bucket rate limits, streamed 25 MB body caps, CRL revocation and a CN allowlist bound what any single stolen certificate can do.

Hardened to the metal

No-login service user, root-owned code, syscall-filtered systemd units, capability-free read-only containers — and installers that fail loudly if mTLS isn't enforced.

Deploy

Your stack, your infrastructure

Every path ships hardened and documented, with a per-runtime runbook covering install, certificate lifecycle, updates, monitoring, troubleshooting and disaster recovery.

Docker

Bare metal / VPS

sudo deploy/install/install-go.sh — creates the service from scratch and self-checks that a request without a client certificate is refused. Runbooks: runbooks/RUNBOOK-*.md.

Cloudflare Worker with mTLS enforced at the edge (API Shield); same routing table, same pass-through contract.
